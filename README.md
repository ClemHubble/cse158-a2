# Detecting AI-generated choreography in Dance Dance Revolution step charts

Binary classification of human-authored vs AI-generated step charts using features derived from the Dance Dance Convolution model.

> [!NOTE]
> Originally an assignment for [CSE 158](https://cseweb.ucsd.edu/classes/fa25/cse258-a/) at UC San Diego.

## Background

This project uses step chart data generated by the [Dance Dance Convolution](https://github.com/chrisdonahue/ddc) (DDC) model to train classifiers that distinguish between human and AI choreography. The original paper can be referenced [here](https://arxiv.org/abs/1703.06891).

### Datasets

Two step chart packs are used:

| Dataset | Songs | Description |
|---------|-------|-------------|
| [Fraxtil](https://search.stepmaniaonline.net/packs/fraxtil) | 90 | Three packs: Arrow Arrangements, Beast Beats, Tsunamix III |
| [In The Groove](https://search.stepmaniaonline.net/packs/in+the+groove) (ITG) | 133 | In The Groove 1 & 2 official packs |

The `data/` folder is structured as such:
- `unprocessed/` contains raw data generated from DDC's scripts
- `real/` contains normalized JSONs with human-made charts
- `artificial/` contains charts generated with the DDC model

### Structure

Each chart has a difficulty level that affects step density and complexity:

| Difficulty | Typical steps/sec | Characteristics |
|------------|-------------------|-----------------|
| Beginner | ~1 | Quarter notes only, simple patterns |
| Easy | ~2 | Eighth notes, basic transitions |
| Medium | ~3 | Sixteenth notes, some jumps |
| Hard | ~4 | Dense patterns, jumps, holds |
| Challenge | ~6 | Complex rhythms, crossovers, streams |

Each step is encoded as a 4-character string `[L,D,U,R]` where:
- `0` = off
- `1` = tap
- `2` = hold start
- `3` = hold release

### DDC limitations

The DDC model has several constraints that may introduce detectable artifacts:

- All generated charts assume 125 BPM regardless of actual song tempo, as the model has no temporal conception
- Step placement involves peak-picking on CNN-LSTM probability outputs with difficulty-specific thresholds
- Step selection involves conditional LSTM samples from learned distribution without direct audio conditioning
- The step selection model treats holds as independent events rather than sustained actions, as they are encoded in this manner
- The model was trained primarily on electronic music with constant tempo

## Usage

### Requirements

Requires Python 3.12+ and [uv](https://github.com/astral-sh/uv).

```bash
uv sync
```

### Generating AI charts

The DDC model runs as a Docker container:

```bash
docker run -it -p 8080:80 chrisdonahue/ddc:latest
```

Then sequentially run `02-generate-ai-charts.ipynb` to generate charts for all audio files.

### Notebooks

| Notebook | Description |
|----------|-------------|
| `01-normalize-human-charts` | Converts DDC dataset format to simplified JSON with time (seconds) and step fields |
| `02-generate-ai-charts` | Sends audio to DDC server, parses returned `.sm` files into JSON |
| `03-convert-to-seconds` | Ensures all charts use seconds (all DDC-generated charts are 125bpm) |
| `04-eda` | Exploratory data analysis, validation, and visualization |
| `05-classification` | Training models with explicit feature engineering |
| `06-classification-implicit` | Training models with feature learning |
| `07-comparison`| Evaluated performances of all models |

Run notebooks from the `notebooks/` directory:

```bash
cd notebooks
uv run jupyter notebook
```
